## 一、项目背景

全国硕士研究生招生考试（以下简称"考研"）报名人数连续多年处于高位。对考生而言，考研不是一场知识储备的比拼，更是一场**长期规划能力**的比拼——从确定目标院校，到拆解为各阶段任务，再到把任务落到每一天的具体时间表，中间任何一个环节断链，都会导致备考节奏崩塌。

市面上现有的备考工具大致分三类：

| 类型 | 代表 | 局限 |
|---|---|---|
| 计时/打卡类 | Forest、番茄钟 | 只记录时长，不参与规划 |
| 题库/课程类 | 各机构 App | 提供内容，不做个性化排期 |
| 通用 AI 助手 | 各类大模型对话 | 不了解用户真实数据，且高度依赖云端 |

这些工具的共同问题是：**它们是被动的记录工具，而不是主动的规划主体。** 学生仍然需要自己判断"今天该学什么、学多久"，而恰恰是这个判断最容易在疲惫和焦虑中失效。

与此同时，两个现实约束长期被忽略：

- **网络与成本约束**：多数校园场景（图书馆、自习室、宿舍）网络不稳定，而主流 AI 功能必须联网、且需要用户自行申请并付费的 API Key。
- **隐私约束**：学习目标、每日作息、报考院校属于个人敏感信息，用户普遍不愿意上传到第三方服务器。

"帮帮林"正是在这两个约束下设计的：**一个本地优先、离线可用、以目标为驱动、能自主完成规划决策的 AI 智能体。**

## 二、痛点问题分析

### 痛点 1：固定计划必然失效

传统备考计划一旦生成就是静态的。但学生的每一天都不一样——上午突然有课、下午要兼职、晚上聚餐、明天要做饭。计划与现实脱节后，学生要么硬撑（效率极低），要么放弃（计划作废）。现有工具没有能力根据"今天实际可用时间"重新规划。

### 痛点 2：AI 能力依赖云端，断网即瘫痪

主流 AI 备考助手要求用户配置 API Key 并联网。一旦断网、密钥失效、额度用尽，整个"智能"部分立即消失，退化为一个普通的待办清单。学生最需要 AI 的场景（临时调整计划）恰恰最可能发生在网络不佳的环境。

### 痛点 3：目标与每日计划脱节

学生普遍会设定目标（"考西安邮电大学计算机学硕""12 月过六级""10 月参加数学竞赛"），但这些目标只停留在愿望层面，没有转化为每天可执行的具体动作。目标和日程是两张皮。

### 痛点 4：择校信息高度分散

院校招生数据（学硕/专硕各招多少人、扣除推免后统招多少人、近年复试线）分散在各校研究生院官网，格式不一、更新频繁。学生需要逐个学校翻找，耗时且容易出错。

### 痛点 5：数据隐私顾虑

学习目标、作息习惯、报考志愿属于高度个人信息。将这些数据上传云端服务器，是许多用户使用 AI 工具时的心理障碍。

## 四、目标用户群体与功能需求

### 4.1 目标用户

**核心用户（Primary）**
- 在校备考硕士研究生的本科生，以计算机、电子信息等理工科专业为主
- 特征：有明确升学目标，但缺乏系统规划能力；每日可支配时间波动大；对 AI 工具有兴趣但不愿付费配置

**次要用户（Secondary）**
- 准备各类学科竞赛、英语等级考试、职业资格认证的学生
- 特征：目标周期短（1–3 个月），需要精确的倒计时驱动

**扩展用户（Tertiary）**
- 高校就业指导中心、辅导员：需要批量了解学生备考分布与进度

### 4.2 用户需求映射

| 用户诉求 | 对应功能 |
|---|---|
| "我不知道今天该学什么" | 目标驱动自动排期（F4） |
| "我明天下午才有空，帮我重排" | 自然语言空闲时段识别 + 动态重排（F2、F4） |
| "我怕坚持不下去" | 目标倒计时 + 连续打卡（F3） |
| "这个学校招多少人" | 院校招生数据模块（F5） |
| "我不想把数据传上去" | 本地优先架构（N3） |

## 五、开发工具

| 类别 | 工具/技术 | 说明 |
|---|---|---|
| 前端 | HTML5 + 原生 JavaScript（ES5） | 单文件交付，零构建、零依赖 |
| 后端 | Node.js（内置 http/crypto/fs 模块） | 无第三方框架，降低部署门槛 |
| 数据存储 | 浏览器 localStorage + 服务端 JSON 文件 | 本地优先，可选云同步 |
| 本地大模型 | WebLLM + Qwen2.5-1.5B-Instruct | 浏览器内 WebGPU 推理 |
| 在线大模型 | DeepSeek / 通义千问 / 智谱 GLM | 可选增强，用户自配密钥 |
| 桌面打包 | PyInstaller（启动器） | 双击即用，自动拉起本地服务 |
| 版本管理 | Git | 迭代管理 |

**为什么选择零依赖技术栈**：参赛作品的演示环境不可控，任何构建链或依赖安装失败都会导致演示失败。零依赖单文件架构保证"拷贝即用"，这是面向比赛与真实分发的工程选择。

### 6.1 系统架构

```
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│            智能体决策引擎（核心）              │
│  ① 接收请求 → ② 意图识别 → ③ 参数提取         │
│  → ④ 目标匹配 → ⑤ 策略选择 → ⑥ 执行反馈       │
└──────────────────┬──────────────────────────┘
                   │
     ┌─────────────┼─────────────┐
     ▼             ▼             ▼
┌────────┐  ┌───────────┐  ┌──────────┐
│ L1 规则 │  │ L2 本地模型 │  │ L3 在线API│
│  引擎   │  │  WebLLM   │  │DeepSeek等 │
│ 离线可用 │  │ 数据不出机 │  │ 可选增强  │
└────────┘  └───────────┘  └──────────┘
     ▲
     └── 自动降级：L3 → L2 → L1
```

### 6.2 AI 三层推理架构（核心创新点）

这是本作品最核心的设计。**大多数 AI 应用只有"调用模型"一条路径，模型不可用即全盘失效。帮帮林设计了三条可自动降级的推理路径：**

**L1 · 本地规则引擎（默认，始终可用）**
- 完全本地运行，零延迟、零成本、无需网络
- 包含：意图分类器、时间区间解析器、目标匹配器、排期求解器
- 承担绝大部分日常请求

**L2 · 浏览器内置大模型（可选升级）**
- 基于 WebLLM 在本地浏览器内运行 Qwen2.5-1.5B-Instruct
- 数据 100% 不出设备，兼顾能力与隐私
- 首次加载约 1.2 GB，缓存后永久离线

**L3 · 在线大模型 API（可选增强）**
- 支持 DeepSeek、通义千问、智谱 GLM-4
- 用户自行配置密钥，用于需要更强生成能力的场景

**降级策略**：系统实时探测各层可用性，按 L3 → L2 → L1 顺序自动选择，且**对用户完全透明**——用户永远不会看到"AI 离线"这样的失败提示，只会得到稍简但依然可用的结果。

### 6.3 智能体决策链

智能体处理一次请求的完整链路，共六步，**全部在界面上可视化呈现**：

| 步骤 | 内容 | 技术实现 |
|---|---|---|
| ① 接收请求 | 获取用户自然语言输入 | 文本归一化（全角/半角、标点统一） |
| ② 意图识别 | 判定为排期/问答/查院校/加目标等 | 关键词加权 + 正则模式匹配 |
| ③ 参数提取 | 抽取空闲时段、忙碌时段、日期 | 时段区间解析（支持全角冒号、多区间、上下午推断） |
| ④ 目标匹配 | 关联用户已设目标及剩余天数 | 目标库检索 + 倒计时计算 |
| ⑤ 策略选择 | 选择 L1/L2/L3 推理路径 | 可用性探测 + 自动降级 |
| ⑥ 执行反馈 | 生成结果并写回计划/目标模块 | 排期求解 + 数据持久化 |

### 6.4 目标驱动排期算法

这是作品的算法核心。输入"用户空闲时段 + 目标集合"，输出"可执行课表"：

1. **时段解析**：从自然语言中提取所有空闲区间，归一化到分钟级时间轴
2. **上下午推断**：依据"早上/上午/下午/晚上/中午"等前缀自动判定 AM/PM
3. **冲突消解**：若同时给出明确区间与模糊时段（如"下午 3:00-5:00 有空"），**明确区间优先**，避免被泛化猜测覆盖
4. **目标优先级排序**：按目标截止日临近程度排序，越近的目标越优先占位
5. **贪心装箱**：按时长需求将任务依次装入空闲区间，区间剩余不足 15 分钟则跳过
6. **结果校验**：若外部大模型返回结果越界（落在忙碌时段），自动过滤，保留率过低则回退到规则引擎重排

## 七、作品功能详述

### 7.1 目标管理（AI 作用：自然语言解析）

**功能**：用户可用口语直接录入目标，系统自动识别类型、日期、院校与学位类型。

**AI 核心作用体现**：
- 输入"9.23 全国大学生数学竞赛校赛" → 自动解析为「竞赛」类目标，日期 2026-09-23
- 输入"我想考西安邮电大学计算机学硕" → 自动解析为「升学」类目标，院校=西安邮电大学，专业=计算机，学位=学硕
- 系统同时提供推荐目标库（数学竞赛、四六级、软考、PAT、CCF CSP）

### 7.2 首页目标看板（AI 作用：倒计时与数据关联）

- 展示全部进行中目标及剩余天数
- 升学目标自动关联展示该院校的**学硕统招人数 / 专硕统招人数 / 总招生数 / 近年复试线**
- 目标按截止日期排序，临近目标高亮预警

### 7.3 目标驱动自动排期（AI 作用：核心）

**使用场景**：用户在首页或 AI 面板输入"明天上午有课，下午 2 点到 3 点 40 有空，晚上 9 点到 10 点半也有空，帮我排学习计划"。

**处理过程**：
1. 解析出三个空闲区间
2. 匹配用户目标（数竞、六级、升学）
3. 按目标优先级 + 核心学科（数学/英语/408）生成课表
4. 全部任务严格落在这三个区间内

**输出示例**：

| 时间 | 任务 |
|---|---|
| 14:00-14:50 | 英语（背单词+阅读） |
| 14:50-16:20 | 数学学习（核心） |
| 16:20-16:40 | 数学竞赛题专项（数竞目标） |
| 21:00-21:40 | 408 专业课 |
| 21:40-22:00 | 复盘 + 明日计划 |

### 7.4 智能体决策链可视化（AI 作用：可解释性）

用户每次与 AI 交互，界面分步呈现智能体的分析决策过程：

```
① 接收请求  "明天下午3点到5点有空，帮我排学习计划"
② 意图识别  → 智能排期
③ 参数提取  → 空闲 15:00-17:00
④ 目标匹配  → 数竞（剩44天）· 六级（剩93天）
⑤ 策略选择  → 本地规则引擎（离线可用·零延迟）
⑥ 执行反馈  → 生成 5 项任务并写入每日计划
```

**设计意义**：AI 应用普遍存在"黑箱"问题，用户不知道 AI 依据什么做出决策。帮帮林把决策链显式暴露，既提升信任度，也让用户在结果不理想时能准确指出问题所在。

### 7.5 学科学习模块

覆盖数学、英语、408、政治四科，提供按日推进的课程任务、进度记录与错题整理，并与每日计划联动。

### 7.6 院校数据模块

内置 **11 所院校**的计算机类招生数据，支持自然语言查询（如"东南大学计算机招多少""杭电专硕统考多少"）。

**覆盖范围（体现普适性，而非服务单一考生）**：

| 层次 | 院校 | 省份 |
|---|---|---|
| 985 | 东南大学、浙江大学 | 江苏、浙江 |
| 211 | 西安电子科技大学、南京航空航天大学、南京理工大学、安徽大学、合肥工业大学 | 陕西、江苏、安徽 |
| 双一流 | 南京邮电大学 | 江苏 |
| 双非 | 西安邮电大学、杭州电子科技大学、浙江工业大学 | 陕西、浙江 |

覆盖**陕西、江苏、浙江、安徽**四省，兼顾顶尖 985、行业特色 211、邮电类双一流与就业强校双非，可服务不同层次、不同地域考生的择校需求。

**数据字段**：学硕/专硕的**拟招总数、统考招生数、推免数、复试线**，以及专业代码级明细（如 081200 计科、085404 计技）。

**数据治理**：每条数据均标注**官方来源链接**（各校研究生院招生专业目录/复试录取方案）与**核验状态**：
- `✓ 更新于 X（已核验）`
- `⚠ 更新于 X，待官方核验`
- `⚠ 内置参考数据，非官方核验值`
- 超过 7 天自动标记"可能已过期"

官方未公布的字段（如部分院校统考/推免拆分）如实显示"未公布"，不做推测填充。

### 7.7 AI 助手对话

支持进度分析、心态疏导、学科答疑、院校推荐等对话场景；所有回答基于用户**真实学习数据**生成，而非通用模板。

## 八、使用说明与交互指南

### 8.1 启动

- **方式一**：双击项目目录中的 `帮帮林.exe`，自动启动本地服务并打开浏览器
- **方式二**：命令行执行 `node server.js`，浏览器访问 `http://localhost:3210`

### 8.2 首次使用流程

```
启动 → 填写档案（院校/专业/目标）→ 进入首页
     → 添加目标 → 输入明日空闲时段 → 生成计划
```

### 8.3 典型交互

| 用户操作 | 系统响应 |
|---|---|
| 在 AI 面板输入"加目标：12 月六级" | 自动创建目标，首页显示倒计时 |
| 输入"明天上午有课，下午有空，帮我排" | 解析时段并按目标生成课表 |
| 点击首页「我的目标」 | 进入目标管理页，可增删改目标 |
| 在每日计划页输入修改指令 | 支持"改成/删除/添加/延后/按空闲重排" |

### 8.4 登录说明

- 支持账号登录（数据云同步、查看考研人数概况）
- 支持**本地使用**（不联网，数据仅存本机，功能完整）

## 九、应用前景

### 9.1 直接价值

- 降低规划门槛：学生无需掌握规划方法，用口语即可获得可执行课表
- 提升执行率：计划随现实动态调整，避免"计划作废"
- 保护隐私：本地优先架构消除数据上传顾虑

### 9.2 扩展场景

| 方向 | 说明 |
|---|---|
| 多考试类型 | 框架可迁移至公考、留学、职业资格考试 |
| 校园部署 | 面向高校就业指导中心的班级级进度看板 |
| 内容联动 | 与课程平台对接，按计划推送对应学习资源 |

### 9.3 社会价值

作品针对的是**教育资源相对薄弱院校的学生**——他们往往缺乏专业的备考指导，也难以负担付费规划服务。将规划能力以零成本、离线可用的方式交付，具有明确的教育公平意义。

| 免费层 | 本地全部功能（规则引擎 + 目标 + 排期） | 永久免费 |
| 增强层 | 院校数据实时更新、云同步、深度分析 | 订阅制 |
| 机构层 | 院校/机构批量部署与数据看板 | 授权收费 |

**核心原则**：AI 规划能力本身永久免费。这与当前大量 AI 产品"免费试用后收费"的模式形成差异，也是作品的社会价值所在。

### 10.2 成本结构

- 本地规则引擎路径：**零边际成本**（不调用任何付费 API）
- 在线增强路径：由用户自配密钥，成本不由平台承担
- 主要成本为院校数据维护与服务器托管

### 10.3 推广路径

1. 以考研社区、院校论坛为种子渠道
2. 与目标院校就业指导中心合作试点
3. 通过软著与赛事背书建立信任
